## 推进规则

- 默认在 `dev` 开发，保留已有未提交改动；提交、推送按当批用户指令执行，不自动合并 `main`，不发布 npm、不改 Git 作者信息。
- 每批同时维护实现、回归测试、公开类型、根/按需入口、主题、活例和变更记录。没有新增 API 时不为凑清单改入口。
- 正常操作、禁用/只读、required、非法/重复数据、动态替换、旧 DOM 事件、焦点、提交/reset 与卸载清理按组件风险验证。
- 每批通过 `pnpm check`；新增可见交互还需真实浏览器明暗主题、自定义色、390px 窄屏和键盘检查。浏览器未验证时明确记录，不能标记为全量验收。
- 新业务接口在对应“接口冻结”单元明确后实施。远程请求、鉴权、路由、时区转换与持久化由应用负责，组件不暗中接管。
- 若 P1 工作超出预算，顺延 P2 新组件，保留回归和联动验收时间，不降低质量门禁。
